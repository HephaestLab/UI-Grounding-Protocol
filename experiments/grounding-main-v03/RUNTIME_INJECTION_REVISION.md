# Runtime-injection revision

Date: 2026-08-29

Before confirmatory outcomes were collected, the project owner clarified that
UGP is an installed UI semantic protocol. Its experimental condition therefore
requires an application retrofit and runtime-emitted Capsule. The previous v0.3
harness instead synthesized a Capsule from ordinary DOM/AX observations.

The 212 completed calibration episodes remain engineering evidence for the
actor, reset, scoring, sealing, and audit paths. They are not calibration or
effect evidence for the runtime-injected UGP intervention.

The revised sequence is:

1. Use `ugp-retrofit` to author one versioned adapter per live application from
   a frozen authority manifest.
2. Emit Capsules from the live application Binding registry.
3. Give equal-authority RAG, MCP, and NLWeb controls projections of the same
   authoritative fact set; keep visual/structural controls native.
4. Run the complete 170-task ST-WebAgentBench SuiteCRM slice as an adaptive
   development experiment across eight methods and two models.
5. Use SuiteCRM outcomes and traces to revise the Skill/protocol when needed.
6. Freeze the resulting implementation and validate generalization on WebMall,
   ST GitLab/ShoppingAdmin, and WorkArena without outcome-guided changes.

ScreenPR and ScreenQA have no corresponding live application/backend that can be
retrofitted. They remain auxiliary representation studies and are not reported
as native UGP deployment evidence.

## SuiteCRM development adapters

- v3 separated semantic choice labels from exact executable arguments and
  distinguished schema presence, layout reachability, and live Bindings.
- v4 rejects unresolved localization tokens as semantic labels and preserves
  authoritative field identity and editable priority across relationship-picker
  inputs and live option overlays. This revision is task-agnostic and follows
  the dynamic-surface and semantic-label acceptance rules above.
- v5 separates relationship search-query text, candidate options, and the
  selected entity. Query text no longer emits a business-field current-value
  fact or a verification link, and relationship commit compatibility remains
  closed until application state reports a selected entity. This prevents a
  typed search string from being mistaken for a committed relationship.
- v6 makes the actionable boundary explicit: only controls with declared
  executable operations enter `interactionBindings`, each relationship option
  has one canonical executable Binding, and option descendants remain context. A
  nonempty relationship query that closes without a verified selection is an
  unresolved transition; commit Bindings are withheld until the application
  reports a selected entity or a declared cancellation resets the transition.
  Fail-closed snapshots also retain the full versioned quality schema.
- v7 makes unresolved relationship selection state transaction-scoped rather
  than visibility-scoped. A pending query survives local form-tab and panel
  changes and continues to withhold commit Bindings. It clears only on a
  post-query selected-identity transition, a matching canonical candidate
  activation followed by selected state, explicit query cancellation, or
  transaction-surface exit; a pre-query selected value is baseline evidence, not
  proof of completion.

## Post-v7 semantic realignment

The v7 audit exposed a broader design issue: the SuiteCRM adapter's primary
Capsule is a page-level `crm.module-state` aggregate whose nested controls do
not each have an independently complete Description. The v2–v7 line is therefore
frozen as developmental evidence for interaction and lifecycle semantics, not as
complete evidence for UGP's original referent-level semantic-transfer claim.

Paid actor execution is stopped. The next version is blocked on the offline
gates in [`SEMANTIC_REALIGNMENT_PLAN.md`](SEMANTIC_REALIGNMENT_PLAN.md) and the
first-principles contract in
[`../../spec/drafts/v0.2/FIRST_PRINCIPLES.md`](../../spec/drafts/v0.2/FIRST_PRINCIPLES.md).
Development resumes with 12 paired tasks (24 episodes), then an independent
held-out stage, before any new 200-episode confirmatory run.
